# human-in-loop v0.1.3

Source-only release of the accepted headless, iMessage-only product. No binary
assets, notarized installer, npm publication, or general binary distribution are
provided by this GitHub Release.

- Apple Messages via iMessage is the only maintained remote channel. The retired enterprise messaging channel has
  been removed from current runtime, configuration, and dependencies. Explicit
  iMessage service selection and no-SMS fallback remain enforced.
- Replies use decimal `<TOKEN>-<OPTION_NUMBER>` grammar, for example `48273-1`.
  Bare choices, malformed replies, stale tokens, and uncorrelated rows fail closed.
- Rich multiline decision bodies remain supported. A terminal notification keeps
  its report locator in the same message; the quoted HTTP(S) locator was qualified
  as tappable without a large Apple Rich Link Preview.
- Routine progress notifications default to zero, with at most one terminal
  `notify_human` attempt per logical task.
- Onboarding is simplified; dedicated-Bot automatic login remains optional and
  opt-in. Canonical HOME, stable signing, and existing TCC boundaries are retained.
- Legacy visible AskHuman tray/menu-bar login startup and the upstream AskHuman
  updater are retired from production. Headless daemon, Codex MCP, dedicated Bot
  worker, and public-basic `imsg` transport remain supported.
- Bounded Bot-owned history reconciliation catches watcher misses using the same
  strict chat, send-row, GUID, token, option, deadline, and terminal-state resolver.

The public MCP tools remain exactly `ask_human` and `notify_human`. The accepted
real phone qualification produced one canonical `received_correctly` result
from `imessage` after one real send, with watcher/request/client cleanup. This
release reuses that accepted evidence because runtime and transport source are
unchanged apart from version metadata; no duplicate real decision was sent.
