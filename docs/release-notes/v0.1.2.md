# human-in-loop v0.1.2

This release adds an optional multiline `ask_human.detail` field for substantive decision evidence while keeping `question` concise and `context` compact. Meaningful line breaks are preserved through the canonical confirmation and maintained renderers.

iMessage decision bodies default to 1,000 Unicode characters and complete decision messages default to 1,500 characters. Users may raise these operational limits up to the defensive ceilings of 4,500 detail characters and 5,000 rendered characters. Invalid budgets and oversized payloads fail closed without truncation and produce fixed redacted diagnostic reasons.

Existing callers that omit `detail` remain compatible. The public MCP surface, result shape, coordinator, iMessage-only/no-SMS transport, Bot/TCC topology, daemon lifecycle and `notify_human` semantics are unchanged.
