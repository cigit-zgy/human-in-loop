# Context

The target workflow is Codex/Agent execution that pauses when a human decision is required. The user wants to answer from an iPhone when away from the Mac. The maintained remote surfaces are limited to Feishu and Apple Messages. Apple delivery must remain free iMessage and must never fall back to carrier SMS/MMS/RCS.

The user also requires a structured, bounded decision presentation. Images are included only when they are genuinely needed as decision evidence.

# Prior-art gate

## Naituw/AskHuman

Coordinates inspected:

- https://github.com/Naituw/AskHuman
- revision `77e2e576347f94ef203bc2426b73a18749cb4e92`
- MIT license

Observed relevant design:

- single `AskHuman` CLI for Agent → human questions;
- Tauri/Rust + Vue application;
- channel abstraction with coordinator/preemption;
- structured confirmation models (`ConfirmRequest`, context fields, choices/results);
- Feishu long-connection + interactive card channel;
- multiple channels race and first valid terminal answer wins;
- existing settings/history/Agent integration.

Disposition: **ADAPT**.

Design consequence: use AskHuman as the application/core basis instead of writing a new HITL framework. Narrow the maintained product surface to Feishu + iMessage and preserve the existing canonical/coordinator ideas.

## openclaw/imsg

Coordinates inspected:

- https://github.com/openclaw/imsg
- revision `646ea7af9616dc3e6406d86aa269bf4fb1b07a76`
- MIT license

Observed relevant design:

- native Swift CLI for reading, watching, and sending iMessage/SMS from macOS;
- reads local Messages database and sends through Messages.app automation;
- NDJSON/JSON-RPC interfaces intended for scripts/agents;
- text and file sending;
- explicit `--service imessage` mode;
- inspected docs state explicit iMessage mode does not use SMS fallback;
- standard operation does not require private IMCore injection.

Disposition: **REUSE**.

Design consequence: use `imsg` as an installed external dependency. Do not copy or fork its source into the product. Restrict calls to documented public-path features and always force iMessage.

## OpenAI Agents SDK HITL

Source:

- https://github.com/openai/openai-agents-python

Observed precedent: structured interruptions carry action details; human decisions are explicit approve/reject/edit-style results; execution resumes from stored interruption state; approval paths fail closed when arguments cannot be safely interpreted.

Disposition: **REFERENCE_ONLY**.

Design consequence: preserve explicit structured decision identity and fail-closed behavior rather than inferring approval from free-form conversational text.

## LangGraph HITL

Source:

- https://github.com/langchain-ai/langgraph

Observed precedent: pause → serialize interrupt payload → human selects explicit decision → resume; pending action identity is durable and side effects should occur only after approval/resume.

Disposition: **REFERENCE_ONLY**.

Design consequence: request correlation and explicit resume semantics are treated as protocol concerns, not presentation details.

## BlueBubbles and full message relays

BlueBubbles was inspected as a capable Messages server/relay precedent. It owns substantially more infrastructure than required for a single-user Mac ↔ iPhone approval channel.

Disposition: **REJECT** for this project.

Reason: unnecessary server/backend surface, larger operational/trust boundary, and no need for cross-platform Messages clients when the user already owns the Mac + iPhone pair.

# User + ChatGPT adjudication

Accepted:

```text
AskHuman core                  ADAPT
AskHuman Feishu channel        REUSE/ADAPT in-place
openclaw/imsg                  REUSE as external dependency
OpenAI/LangGraph HITL pattern  REFERENCE_ONLY
```

Product channels:

```text
Feishu
Apple Messages (iMessage only)
```

Explicit exclusions:

```text
WeChat
Telegram
Slack
DingTalk
SMS
MMS
RCS
paid messaging gateway
carrier fallback
BlueBubbles server
private IMCore/SIP-disabled path
```

Apple Messages will use explicit iMessage-only sends and fail closed if the destination cannot use iMessage. There will be no user setting that enables automatic or SMS service selection.

The iMessage surface is intentionally narrower than Feishu. Initial iMessage support is one bounded structured confirmation with 2–6 choices and an exact tokenized numeric reply. Complex requests are Feishu-only rather than being partially rendered.

An iMessage decision may include one caller-supplied PNG/JPEG image, maximum 5 MiB, when the request already includes that image. The renderer never invents an image and does not accept user reply images as a confirmation answer in the first version.
