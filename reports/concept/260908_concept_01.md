# Context / problem

The existing same-account self-message path can prove a strictly correlated Messages row and canonical answer, but it does not reliably produce a genuine incoming-notification experience on the user's iPhone. That makes it unsuitable as the production and release-qualified Apple Messages topology.

The User already has a second Apple Account available for Bot use. The main requirement is to preserve the normal `Guangyao Zhao` macOS account, personal Apple Account, and personal Messages.app while giving human-in-loop an independently owned Apple transport session.

# Compared options

## A — switch the current macOS user's Messages account

Run human-in-loop from the current `Guangyao Zhao` macOS user but switch Messages.app from the personal Apple Account to the Bot Apple Account.

This is rejected as the production default because it disrupts the User's personal Messages identity and mixes personal and Bot ownership, database state, permissions, and lifecycle in one macOS profile.

## B — dedicated macOS user and Bot Apple Account

Create a dedicated `human-in-loop` macOS user, sign its Messages.app into the existing second Apple Account, and run the Bot transport worker and `imsg` within that user's active graphical session. The main coordinator remains with `Guangyao Zhao` and reaches the worker through a narrow authenticated local IPC boundary.

This is accepted. It separates:

```text
personal Messages
Bot Messages
chat.db ownership
TCC permissions
Apple Account identity
runtime/session lifecycle
```

It also leaves the User's personal Messages login and normal use unchanged.

## C — dedicated Mac or heavier deployment

Move the Bot Apple Account to a separate Mac or another heavier always-on deployment.

This is rejected as the production default because it adds hardware and operational burden that the dedicated local user boundary does not currently require.

# Adjudication

Accepted production default: **B — dedicated `human-in-loop` macOS user plus independent Bot Apple Account**.

Rejected production defaults: **A** and **C**.

The production sender is the Bot Apple Account and the recipient is the User's personal Apple Account. Same-account self-message remains only development/diagnostic compatibility and cannot establish production readiness, release qualification, or notification qualification.

The first setup is manual. After setup, sleep, lock, and Fast User Switching do not require another login while the Bot user session remains active. A reboot requires the User to establish the `human-in-loop` login session once before Apple Messages can become ready again.
