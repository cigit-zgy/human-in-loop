GitHub can technically relay an external trigger to a local Mac through Issues, repository dispatch, workflows, or a self-hosted runner, but that approach was rejected as the maintained runtime architecture. It persists or routes decision state through repository infrastructure, introduces asynchronous event/polling semantics, and couples human confirmation to GitHub availability and permissions. The repository is public, which also makes a repository-attached self-hosted runner an inappropriate default security boundary.

The accepted direction is a minimal MCP `ask_human` control interface over the existing canonical confirmation coordinator. Local stdio/process MCP is implemented and verified first; remote ChatGPT deployment is separate and depends on supported mutation-capable custom MCP access. GitHub remains source-control and canonical project-identity infrastructure, not the human-confirmation message queue.
