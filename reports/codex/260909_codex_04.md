## Blocking defect and stop decision

The task-local live client made exactly one installed-MCP `ask_human` call with
a 781-character synthetic Chinese multiline body, seven sections, five stable
choices, no recommendation, and no private WME content. The production daemon
accepted the request and later recorded its normal terminal cleanup line. No
`NoAvailableChannel` or other channel-failure event was recorded for this
request, and the daemon subsequently reported zero active requests.

The verifier then raised an `AssertionError` before saving the MCP result. Its
incorrect assertion was:

```text
successful response result.isError must be undefined
```

The pinned build uses `rmcp 2.2.0`; its `CallToolResult::success` constructor
sets `is_error` to `Some(false)`, which serializes as `isError: false`. The
repository's own production verifier correctly treats only `isError: true` as
failure. The task-local verifier has been corrected to the same rule for future
use, without changing tracked production code.

Because the failed assertion ran before the script copied
`structuredContent` into its redacted evidence file, this run cannot directly
prove the stable selected choice or source channel. The task explicitly says
that an uncertain real qualification must stop before tag/publication and must
not be hidden with a retry. Accordingly, Codex did not issue another request,
did not update the machine Skill pin, and did not create or publish `v0.1.2`.
This is a `TEST_DEFECT` with a blocking loss of release evidence, not a proven
product or transport regression.
