## Changes

- Extended the existing `toml_edit` Codex integration to recognize both the
  current `human-in-loop` entry and its retained `askhuman` compatibility name.
  Install/update removes `HUMAN_IN_LOOP_HOME` only when it resolves to the
  known project-managed `~/.local/share/human-in-loop-codex` location. Absolute,
  tilde, `$HOME`, `${HOME}`, and one-trailing-slash forms are covered without a
  hard-coded username.
- Preserved an unknown custom `HUMAN_IN_LOOP_HOME`, `PATH`, unrelated MCP
  servers, Codex keys, comments, ordering, direct-only ownership semantics, and
  uninstall boundaries. Detection also notices a managed override on a
  secondary recognized product entry so update cannot incorrectly report the
  configuration current.
- Added a typed availability snapshot to canonical confirmation entries.
  Popup, Feishu, and iMessage failures are reduced to fixed reasons such as
  `disabled`, `not_configured`, `worker_unavailable`, `automation_denied`,
  `watch_failed`, `unavailable`, or `failed`; arbitrary transport errors never
  cross the logging API. The coordinator still returns only
  `NoAvailableChannel` and never synthesizes approval.
- Routed every canonical confirmation `NoAvailableChannel` terminal path
  through the same best-effort structured daemon diagnostic. Coordinator
  terminalization occurs before logging, so logging cannot delay the result.
- Used the repository version helper to synchronize `0.1.1` across the Rust,
  Tauri, frontend, npm wrapper, and four platform package manifests; Cargo lock
  identity was updated by the Rust toolchain. Added narrow draft
  `docs/release-notes/v0.1.1.md`. No onboarding, channel, permission, progress
  notification, public MCP schema, dependency, release, or tag redesign was
  introduced.
