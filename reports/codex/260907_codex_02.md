# Changes

- Added the explicit, serialized `distinct_peer` / `same_account` identity mode to runtime configuration, CLI, settings UI, TypeScript types, search metadata, i18n, and README guidance. The default preserves the existing distinct-peer behavior.
- Made an enabled configuration with a non-empty approved recipient valid before a chat id/GUID exists. Health now distinguishes `bootstrap_required` from `not_configured`, and the structured-confirmation candidate registry includes this state.
- Retained the normal collision-safe token allocator and bounded canonical renderer before mutation. The direct send builder remains fixed to `--service imessage --no-sms-fallback`; no auto, SMS, MMS, RCS, carrier relay, private IMCore, or SIP-disabled path was added.
- Added a pre-send row/time boundary and required a structured send receipt containing the sent row id and GUID. After the single send, a bounded global watcher recovers the exact outgoing row, and recent chat metadata must resolve exactly one direct iMessage conversation containing that row before its id/GUID is persisted.
- Started the final chat-scoped watcher from the sent row boundary. This closes the post-send startup window without accepting the outgoing request or older history.
- Added strict reply admission over documented message fields: exact direct chat, row strictly after the sent row, distinct sent/candidate GUID, exact uppercase token plus one ASCII space plus one-based option, active unexpired request, valid option, and no reaction or attachment. When `reply_to_guid` exists, it must equal the sent request GUID.
- Preserved `is_from_me == false` for `distinct_peer`. In `same_account`, either value is eligible only after all other correlation checks pass. Coordinator submission still supplies the canonical wire choice and permits exactly one terminal winner.
- Kept fail-closed behavior for incompatible `imsg`, unreadable Messages data, ambiguous chat resolution, non-iMessage recipients, malformed NDJSON, uncertain send results, and watcher failure. Every final watcher path explicitly kills and reaps its child, with `kill_on_drop` as defense in depth.
- Added deterministic focused tests for same-account self-synced replies, outgoing/stale/wrong-chat/wrong-token/invalid-option/reaction/attachment/reply-GUID/duplicate/late rejection, distinct-peer self rejection, bootstrap readiness, explicit send arguments, ambiguous post-send resolution, configuration/CLI behavior, and runtime channel availability. Added one ignored, environment-gated live test that uses the canonical internal confirmation, production renderer, iMessage adapter, watcher, and coordinator without embedding private data.

# Remaining limitations

- The adapter intentionally handles only bounded single-select structured confirmations that fit the existing iMessage rendering budgets. Unsupported interaction shapes fail closed and may be handled by another configured confirmation channel.
- Same-account acceptance proves an exact correlated row synced into the configured direct chat; it does not and cannot attest which physical device authored that row.
- Initial deterministic chat discovery scans documented local chat metadata and may take about one minute on the current Messages database. It is bounded by a 90-second timeout; post-send resolution uses only the recent-chat window made current by the just-sent row.
- Runtime compatibility is deliberately exact for the pinned `imsg 0.15.1` contract. A different external CLI version reports `imsg_incompatible` rather than being guessed compatible.
