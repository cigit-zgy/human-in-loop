# Finalize public onboarding and release qualification — Codex report

## Changes

ChatGPT had already authored and committed the accepted design, Skill, project
authority, and initial public README contract before local handoff. Codex audited
that candidate and made the following task-scoped implementation repairs:

- Consolidated public macOS onboarding behind `scripts/macos-bootstrap.sh`. It
  derives the primary user, checks the dedicated Bot login session and pinned
  external `imsg` 0.15.1 resources, performs one bounded initial `sudo -v`,
  provisions the stable-signed coordinator/worker path, runs no-message health
  checks, and invokes one real qualification only when no current qualification
  receipt matches live health.
- Added `scripts/macos-setup.mjs` and focused tests. Setup completion is derived
  from the ten required live predicates plus an owner-only redacted fingerprint
  receipt; sender/recipient handles, chat identifiers, tokens, request IDs, and
  message content are not stored in that receipt.
- Extended the existing authenticated Unix-socket worker protocol with a narrow
  recipient-bound restart request. Prepared-host updates replace the signed
  worker binary and request a clean LaunchAgent restart without recurring
  administrator authentication. The client waits for the old authenticated
  socket to disconnect, removing the observed restart/readiness race.
- Added bounded private worker installation through closed JSON on stdin and a
  deferred-start option used only inside initial bootstrap. No arbitrary command,
  path, credential, Apple Account password, or 2FA input was added.
- Corrected the MCP synthetic verifier's macOS Unix-socket path construction by
  requiring an explicitly empty, short task-local root. This was classified as a
  `TEST_DEFECT`; it did not change production semantics.
- Moved pnpm's build allow-list to `pnpm-workspace.yaml` and pinned vulnerable
  transitive JavaScript packages through workspace overrides. No new runtime
  dependency or second coordinator, worker, MCP server, or transport was added.
- Expanded README onboarding with the single setup entrypoint, unavoidable Apple
  UI prerequisites, one qualification, derived completion, and prepared-host
  no-sudo/no-repeat-qualification behavior.

## AI-assisted implementation transparency

Codex generated and modified the implementation, tests, lockfile, onboarding
documentation, and this report under the committed design. The principal control
flow is:

```text
documented bootstrap
→ stable signed local/shared runtime
→ authenticated dedicated-Bot worker
→ no-message readiness
→ derived setup state
→ one installed MCP qualification when required
→ redacted current-health receipt
→ unattended prepared-host updates
```

The implementation keeps existing canonical coordinator and MCP behavior. The
new restart operation is intentionally closed, authenticated by kernel peer
credentials, pinned to the configured recipient, and terminal after its single
acknowledgement. The qualification receipt deliberately carries only structural
verification state and a one-way fingerprint. No private runtime value was added
to source, fixtures, reports, screenshots, or captured logs.
