## Root cause and implementation classification

The incident was reproduced from the committed authority: a legitimate long
review card supplied as `context` became one compact canonical field, then
failed the existing 80-character context-line limit (and potentially the
700-character complete-message limit) before any transport mutation. The
released v0.1.1 transport, canonical configuration, macOS setup, and short MCP
round trip had already been qualified; this task therefore treated the defect
as a missing rich-body interface rather than a channel-readiness failure.

The implementation adds the design's distinct body path instead of weakening
compact metadata. `question` remains concise, `context` remains at two compact
80-character lines, and `detail` maps to the existing canonical
`ConfirmDetail.body_md`. Line endings normalize from CRLF/CR to LF and only
outer whitespace is removed; internal text and meaningful blank lines are not
collapsed or rewritten.
