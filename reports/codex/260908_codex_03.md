# Stabilize macOS TCC identity and one-time Bot permission bootstrap — Codex report

## Changes

- `scripts/install.sh` now refuses ad-hoc production signing on macOS, selects a stable signing identity deterministically, signs an atomic candidate with the fixed `io.github.cigit-zgy.human-in-loop` identifier, records its designated requirement, and fails closed with `RUNTIME_IDENTITY_MIGRATION_REQUIRED` when a replacement does not satisfy the installed identity rule.
- Added `scripts/macos-bootstrap.sh`. Initial host preparation performs one bounded `sudo -v` and a fixed allow-list of non-interactive privileged installation operations. Once the shared runtime is prepared and ownership/identity guards pass, routine signed updates install atomically and restart the Bot worker without sudo.
- Added deployment contract tests covering stable signing, identity guarding, bounded privilege, password-free routine updates, fixed worker paths, and the Apple Events purpose string.
- Added `NSAppleEventsUsageDescription` and a native `AEDeterminePermissionToAutomateTarget` preflight from the exact production worker identity. Health now distinguishes `automation_ready`, `automation_consent_required`, `automation_denied`, and `automation_target_unavailable`; permission prompting is an explicit no-message bootstrap operation.
- Extended the UID-authenticated worker IPC with a closed `automation` operation. Send and confirmation operations re-check Automation before mutation, while the Bot LaunchAgent remains pinned to `/Users/Shared/human-in-loop/bin/human-in-loop` and the external shared `imsg` executable.
- Fixed health ordering so `bootstrap_required` or `ready` is reachable only after Automation and other transport prerequisites pass.
- Preserved the transport contract `--service imessage --no-sms-fallback` and all strict distinct-account reply rules.
- The first real message exposed eventual consistency between a newly created direct chat and immediate post-send history resolution. The bootstrap resolver now performs a bounded read-only retry of chat/history lookup for up to ten seconds. Every candidate must still satisfy the exact sent-row boundary, chat, GUID separation, sent text, token, option, active-request, direction, reaction, and attachment invariants. It never repeats the send mutation.

The committed task and living design were authored by ChatGPT. Codex authored the implementation, tests, macOS bootstrap execution, defect repair, release-candidate qualification, and this report. Existing coordinator, canonical confirmation model, MCP server, iMessage renderer, and worker boundary were reused; no alternate confirmation path was introduced.

## AI-assisted implementation transparency

The engineering choice is deliberately local and narrow: a dedicated self-signed Code Signing identity lives only in the macOS Keychain, while the repository stores only a structural designated requirement for installed-candidate comparison. No key, certificate bundle, password, recipient, Apple credential, or Messages content is tracked. Two independently signed probe candidates satisfied the same stable designated requirement before production installation.

This follows Apple's distinction between stable code requirements and version-specific code identity ([TN3127](https://developer.apple.com/documentation/technotes/tn3127-inside-code-signing-requirements)), and uses Apple's documented Automation authorization API rather than a test message to discover consent ([`AEDeterminePermissionToAutomateTarget`](https://developer.apple.com/documentation/coreservices/3025784-aedeterminepermissiontoautomatet)). Apple documents Automation and protected user data as separate user-controlled privacy gates ([WWDC19 macOS security](https://developer.apple.com/videos/play/wwdc2019/701/)); sudo is not used to bypass either gate.

The external transport remains the project-pinned `openclaw/imsg` execution model. The implementation retains the parent/session permission context and LaunchAgent approach described by the [OpenClaw iMessage deployment notes](https://github.com/openclaw/openclaw/blob/main/docs/channels/imessage.md) and uses the external [`imsg` CLI](https://github.com/openclaw/imsg) without vendoring or altering it.
