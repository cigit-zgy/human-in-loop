# Minimal MCP ask_human control interface — Codex report

## Changes

- Replaced the routed MCP surface with one rmcp STDIO tool, `ask_human`. Discovery exposes no legacy read/todo tools and no generic shell, file, credential, recipient, or transport-command capability.
- Added the bounded input/output schema from `design/05_mcp_interface.md`: stable choice ids, 2–6 choices, optional recommendation/request id/context, local `repository_path`, and only `request_id`, `selected_choice_id`, and `source_channel_id` in the canonical result.
- Mapped the tool into the existing `ConfirmTask` IPC path and `ConfirmCoordinator`; no second confirmation model, coordinator, watcher implementation, server stack, cloud backend, HTTP listener, or GitHub relay was introduced.
- Reused canonical GitHub-origin project resolution and fail-closed behavior for unresolved repository identity. The existing iMessage renderer now consumes the human-facing request source, preserving the required `Codex · human-in-loop` line for MCP-originated requests.
- Added an async daemon client path whose owned IPC connection propagates MCP cancellation/disconnect. Added STDIO EOF cancellation so shutdown reaches the same coordinator and request-owned watcher cleanup path.
- Preserved legacy permission-confirmation validation through an explicit backwards-compatible request origin, while MCP requests cannot carry permission memory or popup-edit state. Active caller request-id collisions fail closed.
- Updated CLI MCP help and the Grok per-tool timeout key to the maintained `ask_human` name.

## AI-assisted implementation transparency

ChatGPT committed the accepted living design and formal task before handoff. The handoff contained an existing rmcp dependency and a legacy multi-tool MCP module, but not this maintained interface. Codex implemented the new tool/router, canonical mapping, cancellation-aware client/transport path, origin validation, regression tests, and verification locally. The observable implementation choice was to keep rmcp and the daemon IPC/coordinator as the only control and decision paths instead of wrapping the CLI or creating a parallel runtime.

During test-driven implementation, the initial routed build failed until the new server symbols existed. A shutdown regression then showed that rmcp drains an EOF while an active handler can remain blocked; wrapping the STDIO reader with EOF cancellation made the test pass. A later full-suite failure was an outdated help assertion and was corrected to distinguish the retained CLI `--show-last` command from the one-tool MCP surface.
