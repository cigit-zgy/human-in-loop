# Codex global integration — Codex report

## Changes

The maintained public stdio MCP surface is exactly `ask_human` and `notify_human`.
The existing rmcp server, canonical confirmation model/coordinator and configured
channel infrastructure remain the implementation owners. No dependency, second
MCP stack/coordinator, generic command/file capability, relay, HTTP listener,
channel, release, tag or visibility change was added.

`ask_human` retains its existing closed input, stable choice result and cancellation
path. Its repository resolver was extracted unchanged for the second real consumer.

`notify_human` has required `source_agent`, `status` and `summary`, with optional
`repository_path`, `context`, `task_id`, `locator` and `notification_id`. Status is
one of `PASS`, `PASS_WITH_LIMITATIONS`, `BLOCKED`, `FAIL`; context is up to two closed
label/value fields. The renderer preserves supplied fields or rejects unsupported
content: 160-character summary, 240-character locator, 80-character context lines,
700-character complete surface. URL credentials, unsafe URI schemes and malformed
URL-looking locators are rejected; evidence locators are never opened.

The response contains only `notification_id`, `delivery_status` (`SENT`, `PARTIAL`,
`FAILED`) and participating maintained channel types in `channel_ids`. `SENT` is a
dispatch outcome, not proof of phone receipt/read. Delivery does not rewrite the
caller's established verdict.

Notifications use separate bounded daemon IPC dispatch, not fake confirmation
choices or a pending decision. Existing iMessage preparation, explicit send and
outgoing-row resolution are reused; the bounded outgoing-receipt watcher is not
an acknowledgement watcher. Feishu uses existing one-way `send_text`. Dispatch is
bounded at 180 seconds; the client includes a 20-second setup allowance. Errors
crossing MCP use fixed non-sensitive messages. No automatic mutation retry was added.

An independent non-decision task tracker makes notification work participate in
graceful drain and ensures forced shutdown cancels/waits before process exit.
