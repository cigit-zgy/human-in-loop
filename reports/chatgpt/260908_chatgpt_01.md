2. 新的 accepted product requirement
==================================

正式 production Apple Messages topology 不再依赖 same-account self-message。

主 macOS 用户：

Guangyao Zhao

HIL 专用 macOS 用户：

human-in-loop

运行模型：

Guangyao Zhao
├─ 用户个人 Apple Account
├─ 用户个人 Messages.app
├─ Codex / Agent / main human-in-loop coordinator
│
└─ authenticated local IPC
↓
human-in-loop macOS user
├─ 独立 Bot Apple Account
├─ Bot Messages.app
├─ Bot imsg
└─ Bot transport worker
↓
iMessage only
↓
个人 iPhone / personal Apple Account

核心 invariant：

sender_account != recipient_account

生产模式必须是：

Bot Apple Account
→ personal Apple Account

same-account self-message 不再属于 production-qualified topology。

==================================================
3. Apple Account 与 macOS user semantics
=======================================

冻结：

Guangyao Zhao

= 用户正常主 macOS account
= 保留用户当前个人 Apple Account
= 保留用户个人 Messages
= 不为 HIL 修改其 Messages login

human-in-loop

= 独立 macOS user
= HIL Apple Messages transport owner
= 使用用户已有的第二个 Apple Account
= Messages.app 登录该 Bot Apple Account
= imsg 和未来 transport worker 在此 user/session 下运行

Bot Apple Account 是真实 Apple Account，不是虚拟 identity。

human-in-loop 项目绝不能保存：

Apple Account password
2FA code
trusted phone number credential
Apple credential/session secret

==================================================
4. First-time setup vs reboot lifecycle
=======================================

第一次部署需要 User 手工：

1. 创建/确认 macOS user：
   human-in-loop

2. 登录该 macOS user。

3. 在此 user 的 Messages.app 登录 Bot Apple Account。

4. 确认 iMessage activation。

5. 为 Bot runtime/imsg 完成：
   Full Disk Access
   Automation → Messages

6. Fast User Switching 回：
   Guangyao Zhao

第一次完成后：

Apple Account / Messages 登录凭据由 macOS/Apple 正常 profile 保存。

睡眠：
不要求重新登录。

锁屏：
不要求重新登录。

Fast User Switching：
Bot session 保持登录时应继续作为 background transport session。

==================================================
5. Reboot hard boundary
=======================

Mac 真正 reboot 后：

不要声称保存了 Apple Account credential 就等于 Bot GUI session 已恢复。

如果：

human-in-loop macOS user 尚未建立登录 session

则：

Apple Messages channel
!= READY

新的正式 health state：

BOT_SESSION_LOGIN_REQUIRED

语义：

Bot account/profile 已配置，
但当前 reboot 后 Bot macOS graphical/login session 尚未建立。

用户提示必须明确类似：

Apple Messages requires the dedicated
“human-in-loop” macOS user to be logged in once after restart.
Log in to “human-in-loop”, then Fast User Switch back to “Guangyao Zhao”.

不要静默失败。

不要要求用户重新输入 Apple Account password，除非 Apple 自己的 Messages/session 已失效。

==================================================
6. Identity health contract
===========================

Apple Messages READY 至少要求：

bot_macos_user == human-in-loop
AND bot_user_session_active
AND bot_messages_account_active
AND bot_sender_identity_verified
AND recipient_identity_verified
AND sender_identity != recipient_identity
AND direct conversation resolves deterministically
AND service == iMessage
AND imsg available
AND required permissions available

新增/冻结 health states：

BOT_SESSION_LOGIN_REQUIRED
BOT_MESSAGES_ACCOUNT_UNAVAILABLE
BOT_SENDER_IDENTITY_UNVERIFIED
SELF_MESSAGE_UNSUPPORTED

已有：

recipient_not_imessage
permission_missing
imsg_missing
messages_unavailable
watch_failed
send_failed
ready

保持。

==================================================
7. SELF_MESSAGE_UNSUPPORTED
===========================

production 配置中：

sender identity 与 recipient identity 属于同一个 Apple/iMessage account topology

→ SELF_MESSAGE_UNSUPPORTED

→ Apple Messages channel 不得 READY

→ 明确提示用户使用 dedicated Bot Apple Account

不要等到 send 以后再发现 iPhone 没通知。

不要把 same-account correlation 继续定义为 production acceptance。

它可以保留为：

development / diagnostic compatibility

但不得：

production READY
release-qualified
notification-qualified

==================================================
8. Notification 必须成为 production E2E criterion
=============================================

以后真实 Apple Messages release E2E 不再只验证：

imsg send success
或
message appeared in chat

必须验证：

Bot Messages identity
→ personal iPhone
→ genuine incoming iMessage
→ iPhone notification presentation
→ User reply
→ Bot imsg watch
→ strict correlation
→ canonical choice

增加：

HUMAN_NOTIFICATION_CHECKPOINT

自动化程序不能假装检测：

声音被听见
震动被感觉到

正式 qualification：

测试时 User 将 iPhone：

locked / not foreground
Messages notifications enabled
Focus/DND 不阻止本次 qualification

发送后 User 明确确认：

notification appeared on lock screen/banner

记录：

notification_presentation = HUMAN_VERIFIED

声音/触觉只能是 optional observation，不是 hard automated assertion。

→ fail closed

10. Bot privacy model
=====================

Bot Apple Account 建议只用于 human-in-loop。

设计中建议：

Photos sync       OFF
Contacts sync     OFF unless explicitly needed
iCloud Drive      OFF
Keychain sync     OFF
Calendar          OFF
other personal iCloud data OFF

Messages in iCloud：

默认不作为 HIL requirement。

Bot 只有一台 Mac transport host 时，不要求开启云端 Messages 同步。

human-in-loop 只保存必要 transport metadata，例如：

bot sender handle
recipient handle
chat id
chat guid
observed service
health/session state

不要保存：

Apple password
2FA
trusted phone credentials
private unrelated Messages history
