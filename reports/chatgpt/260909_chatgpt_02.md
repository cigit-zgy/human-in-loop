## Incident fixed by this hotfix

The released v0.1.0 machine-wide Codex MCP registration could retain a legacy managed environment override:

```text
HUMAN_IN_LOOP_HOME=<legacy isolated human-in-loop-codex home>
```

That stale isolated config had all channels disabled while the canonical runtime config remained healthy, causing:

```text
ask_human -> NoAvailableChannel
notify_human -> FAILED
```

The accepted v0.1.1 candidate:

- migrates only the known human-in-loop-owned legacy HOME override;
- preserves unknown/custom User HOME values;
- keeps MCP, CLI and daemon on one canonical runtime configuration;
- keeps CLI as recovery/debug fallback, not a second production configuration world;
- preserves fail-closed semantics;
- adds fixed, redacted channel-availability diagnostics for `NoAvailableChannel`.

The current machine was already recovered before implementation and canonical iMessage health is `ready` with macOS setup `COMPLETE`.
