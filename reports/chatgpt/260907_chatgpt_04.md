## Required renderer behavior

For every repository-associated confirmation, render:

```text
[HIL · <TOKEN>]
<source> · <repository-name>
<optional compact context line 1>
<optional compact context line 2>

<compact question>

1  <choice>
2  <choice>

Reply: <TOKEN> 1
```

Example:

```text
[HIL · 7F32]
Codex · water-biomodel-agent
ASM3 Stage 4

Use exact fraction grammar for 1/14?

1  Accept
2  Stop

Reply: 7F32 1
```

The project label is exactly the GitHub repository name/slug, e.g.:

```text
cigit-zgy/water-biomodel-agent -> water-biomodel-agent
cigit-zgy/human-in-loop        -> human-in-loop
```

Do NOT use:

```text
owner/repository
GitHub URL
local filesystem path
worktree directory name
branch name
task id
```

as the phone-visible repository label.

For repository-associated requests, the repository label is mandatory decision context and must not be removed by compaction.

A genuinely non-repository interaction may omit the repository label.

## Repository identity source

Prefer canonical repository identity already known to the request/agent/project context.

If runtime derivation is required, resolve from the canonical GitHub remote identity. Do not guess from an arbitrary local directory basename when a canonical remote is available.

Keep implementation minimal. Do not create a new repository-discovery subsystem if an existing project/workspace/git identity path already supplies the required information.

If current canonical confirmation data does not carry enough repository identity, make the smallest transport-independent model/integration change needed so the renderer receives the repository name without coupling canonical semantics to iMessage.
